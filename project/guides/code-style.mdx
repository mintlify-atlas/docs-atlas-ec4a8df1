This guide documents the C++ code style used across lailai's competitive programming solutions and terminal projects. It applies specifically to **algorithm contest C++ code** and is not intended as a general-purpose style guide.

The style prioritizes brevity and clarity for the contest environment: short variable names, no defensive programming, no comments, and minimal boilerplate.

<Note>
  References: [Google C++ Style Guide](https://google.github.io/styleguide/cppguide.html), [Menci's OI Code Style](https://oi.men.ci/code-style-oi/), and [Baoshuo's Code Style Guide](https://oi.baoshuo.ren/code-style-guide/).
</Note>

## General

- Target the **C++17** standard. Avoid features that are not widely supported in contest judges.
- Modifying code style must not change the underlying logic.
- Do not add comments, debug code, or defensive checks.

## Files

- Use **UTF-8** encoding for all source files.
- Source files use the `.cpp` extension — not `.cc` or `.cxx`.
- Indent with **1 Tab** per level. Do not indent blank lines.
- Files must end with exactly **1 blank line**.
- Do not use 2 or more consecutive blank lines.

## Structure

### Headers

Use the universal header. Add other headers only if specifically required:

```cpp
#include <bits/stdc++.h>
#include <bits/extc++.h>
```

### Macros

Use sparingly, only where they meaningfully shorten repetitive expressions:

```cpp
#define ls (u<<1)
#define rs (u<<1|1)
#define mid (l+r>>1)
```

### Namespaces

```cpp
using namespace std;
using namespace __gnu_pbds;
```

### Braces

Braces appear on their own line. Short statements may be written on a single line or with the brace omitted entirely:

```cpp
for(int i = 1; i <= n; i++)
{
    /* code */
}
if(x <= l && r <= y) { gx(u, v, r - l + 1); return; }
if(n % i == 0) return 0;
```

### Main Function

The main function belongs at the **end of the file** and returns `int` with `return 0`:

```cpp
int main()
{
    /* code */
    return 0;
}
```

## I/O

### File I/O

When the problem requires file input/output, add `freopen` at the start of `main`:

```cpp
freopen("problem.in", "r", stdin);
freopen("problem.out", "w", stdout);
```

### Fast I/O

For large data volumes, disable sync and untie cin from cout:

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
```

### Read and Write Style

- Prefer `cin`/`cout` over `scanf`/`printf`.
- Use `'\n'` for newlines — not `"\n"` or `endl`.
- Use single quotes for single characters in output: `cout << 'A'`, not `cout << "A"`.
- Trailing spaces at line ends and extra trailing newlines are acceptable.

```cpp
cout << "Hello, World!" << '\n';
```

## Types

### Type Aliases

Use `using` for common aliases. Avoid macros for type definitions:

```cpp
using ll = long long;
using ld = long double;
using uint = unsigned int;
using pii = pair<int, int>;
using Comp = complex<double>;
```

Choose the narrowest type that fits the data — prefer `int` over `long long`, `bool` over `int` when appropriate.

### Storage

- Define constants with `const`, not macros.
- Avoid `static`, `register`, and `inline` modifiers.
- Define small variables in local scope; use global scope for large arrays.
- Default to static arrays; use `vector` for adjacency lists and dynamic sizes.

```cpp
const int N = 100005;
int a[N];
vector<int> G[N];
```

## Naming

Follow **snake_case** throughout. Names should use English consonants or common abbreviations — not Chinese pinyin. Small variables use short names (typically 1–3 characters).

### Constants

| Name | Purpose | Example Value |
| :--- | :------ | :------------ |
| `N`, `M`, `K` | Data scale | problem max + 5 |
| `mod` | Modulus | `998244353` or `1000000007` |
| `inf` | Positive infinity | `0x3f3f3f3f` (int) or `0x3f3f3f3f3f3f3f3f` (ll) |
| `eps` | Epsilon | `1e-8` or `1e-10` |
| `pi` | Pi | `acos(-1)` |

```cpp
const int N = 100005;
const int mod = 998244353;
const int inf = 0x3f3f3f3f;
const double eps = 1e-8;
```

### Variables

| Name | Meaning |
| :--- | :------ |
| `T` | Number of test cases |
| `n` | Primary data scale |
| `m` or `q` | Number of operations or queries |
| `op` | Operation type |
| `i`, `j`, `k` | Loop indices |

Common variable names:

| Name | Meaning | Name | Meaning | Name | Meaning |
| :--- | :------ | :--- | :------ | :--- | :------ |
| `ans` | Final answer | `cmp` | Comparator | `cnt` | Counter |
| `cur` | Current value | `dep` | Depth | `dis` | Distance |
| `fa` | Parent node | `len` | Length | `mn` | Minimum |
| `mx` | Maximum | `pos` | Position | `res` | Return value |
| `rnk` | Rank | `rt` | Root node | `siz` | Size |
| `son` | Child node | `sum` | Sum | `tag` | Lazy tag |
| `tmp` | Temporary | `val` | Value | `vis` | Visited flag |

### Multi-test Template

When processing multiple test cases with an index:

```cpp
int T;
cin >> T;
for(int _ = 1; _ <= T; _++)
{
    int n, m;
    cin >> n >> m;
    for(int i = 1; i <= n; i++) cin >> a[i];
    while(m--)
    {
        int op;
        cin >> op;
        if(op == 1) /* code */
        else if(op == 2) /* code */
    }
    cout << "Case #" << _ << '\n';
}
```

## Operations

- Use postfix increment/decrement: `x++`, `x--`.
- `sizeof` does not require parentheses around a variable: `sizeof x`.
