Sorting is one of the most ubiquitous primitives in competitive programming. Many problems reduce to sorting once you identify the right key, and understanding the trade-offs between algorithms lets you pick the right tool for each situation — whether you need stability, a custom ordering, or the ability to count inversions as a byproduct of the sort itself.

## Algorithm comparison

$n$ is the number of elements, $m$ is the value range (max − min + 1), and $k$ is the number of digits in radix sort.

| Algorithm | Average | Worst | Space | Stable | Notes |
|---|---|---|---|---|---|
| Bubble sort | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Yes | Educational only |
| Selection sort | $O(n^2)$ | $O(n^2)$ | $O(1)$ | No | |
| Insertion sort | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Yes | Fast for nearly-sorted data |
| Merge sort | $O(n \log n)$ | $O(n \log n)$ | $O(n)$ | Yes | Inversion counting |
| Quick sort | $O(n \log n)$ | $O(n^2)$ | $O(\log n)$ | No | Worst case on sorted input |
| Heap sort | $O(n \log n)$ | $O(n \log n)$ | $O(1)$ | No | |
| Counting sort | $O(n + m)$ | $O(n + m)$ | $O(m)$ | Yes | Only for small integer ranges |
| Radix sort | $O(nk)$ | $O(nk)$ | $O(n + k)$ | Yes | |
| `std::sort` | $O(n \log n)$ | $O(n \log n)$ | $O(\log n)$ | No | Introsort (use this by default) |
| `std::stable_sort` | $O(n \log^2 n)$ | $O(n \log^2 n)$ | $O(n)$ | Yes | When order of equals matters |

<Note>
The theoretical lower bound for comparison-based sorting is $\Omega(n \log n)$, because there are $n!$ possible orderings and each comparison eliminates at most half the remaining possibilities: $\lceil \log_2(n!) \rceil = \Theta(n \log n)$ comparisons are required in the worst case.
</Note>

## `std::sort` — your default choice

In virtually all competitive programming problems, `std::sort` is the right choice. It uses **introsort** — a hybrid of quicksort, heapsort, and insertion sort — giving guaranteed $O(n \log n)$ worst-case performance with very low constant factors.

```cpp sort-basic.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<int> a(n);
    for (int& x : a) cin >> x;

    sort(a.begin(), a.end());               // ascending
    sort(a.begin(), a.end(), greater<int>()); // descending

    for (int x : a) cout << x << ' ';
    return 0;
}
```

## Custom comparators

When sorting structs or applying non-default orderings, pass a comparator as the third argument to `std::sort`. A comparator must define a **strict weak ordering**: it must return `true` if the first argument should come strictly before the second.

```cpp custom-comparator.cpp
#include <bits/stdc++.h>
using namespace std;

struct Event {
    int time, type; // type: 0 = start, 1 = end
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    vector<Event> events(n);
    for (auto& e : events) cin >> e.time >> e.type;

    // Sort by time; break ties by type (starts before ends)
    sort(events.begin(), events.end(), [](const Event& a, const Event& b) {
        if (a.time != b.time) return a.time < b.time;
        return a.type < b.type;
    });

    for (auto& e : events) cout << e.time << ' ' << e.type << '\n';
    return 0;
}
```

<Warning>
A comparator that returns `true` for equal elements violates strict weak ordering and causes **undefined behavior** — typically a crash or infinite loop. Always use `<` (not `<=`) as the base comparison.
</Warning>

## `std::stable_sort` — preserving relative order

When equal elements must retain their original relative order, use `std::stable_sort`. This is $O(n \log^2 n)$ with no extra memory, or $O(n \log n)$ if extra memory is available.

```cpp stable-sort.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    // Sort records by score; equal scores keep their original order
    vector<pair<int, string>> records = {{90, "Alice"}, {85, "Bob"}, {90, "Charlie"}};
    stable_sort(records.begin(), records.end(), [](const auto& a, const auto& b) {
        return a.first > b.first; // descending by score
    });
    // Result: (90, Alice), (90, Charlie), (85, Bob)
    for (auto& [score, name] : records)
        cout << score << ' ' << name << '\n';
    return 0;
}
```

<Tip>
You can always make an unstable sort behave stably by appending the original index as a tiebreaker: sort by `(key, original_index)`. This avoids the overhead of `std::stable_sort`.
</Tip>

## Merge sort — sorting with inversion counting

Merge sort's $O(n)$ merge step naturally counts **inversions** (pairs $i < j$ where $a_i > a_j$) as a side effect. This makes it indispensable for inversion-count problems.

```cpp merge-sort.cpp
#include <bits/stdc++.h>
using namespace std;

using ll = long long;
const int N = 100005;
int a[N], b[N];
ll inv_count = 0;

void msort(int l, int r) {
    if (l == r) return;
    int mid = (l + r) >> 1;
    msort(l, mid);
    msort(mid + 1, r);

    int p1 = l, p2 = mid + 1;
    for (int i = l; i <= r; i++) {
        if (p1 <= mid && (p2 > r || a[p1] <= a[p2])) {
            b[i] = a[p1++];
        } else {
            // Every remaining element in left half forms an inversion with a[p2]
            inv_count += (mid - p1 + 1);
            b[i] = a[p2++];
        }
    }
    for (int i = l; i <= r; i++) a[i] = b[i];
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> a[i];
    msort(1, n);
    cout << "Sorted: ";
    for (int i = 1; i <= n; i++) cout << a[i] << ' ';
    cout << "\nInversions: " << inv_count << '\n';
    return 0;
}
```

## Counting sort — linear time for small ranges

When element values are non-negative integers bounded by a small constant $m$ (e.g., $m \leq 10^6$), counting sort runs in $O(n + m)$ — faster than any comparison sort.

```cpp counting-sort.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n;
    cin >> n;
    const int MAXVAL = 1000001;
    vector<int> cnt(MAXVAL, 0);
    int mn = MAXVAL, mx = 0;

    for (int i = 0; i < n; i++) {
        int x; cin >> x;
        cnt[x]++;
        mn = min(mn, x);
        mx = max(mx, x);
    }

    for (int v = mn; v <= mx; v++)
        while (cnt[v]--) cout << v << ' ';
    return 0;
}
```

## When to use which algorithm

<Tabs>
  <Tab title="General purpose">
    Use `std::sort`. It handles everything from primitives to structs with custom comparators, runs in $O(n \log n)$ worst case, and has the smallest constant factor of any standard algorithm.
  </Tab>
  <Tab title="Stability needed">
    Use `std::stable_sort`, or add the original index as a tiebreaker and use `std::sort`. The tiebreaker approach avoids any overhead.
  </Tab>
  <Tab title="Count inversions">
    Use merge sort with the inversion counter embedded in the merge step. Alternatively, use a Binary Indexed Tree (Fenwick tree) for more flexibility.
  </Tab>
  <Tab title="Small integer values">
    Use counting sort when values fit in a manageable range ($m \leq 10^6$ or so). For even larger ranges with few distinct values, consider coordinate compression + counting sort.
  </Tab>
</Tabs>
